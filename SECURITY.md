# Security policy

## Supported version

Security fixes are applied to the latest release on the `main` branch.

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could expose uploaded data, execute code, exhaust public compute resources, or affect the host. Use GitHub private vulnerability reporting for the repository.

Include the affected version, reproducible steps, impact, and any suggested mitigation. Do not include private experimental data or credentials.

The public demonstration disables server-side material imports. Local installations remain bound to `127.0.0.1` unless the operator explicitly configures another host.
